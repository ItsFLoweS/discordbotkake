# Формат DBK 1

Расширение: `.dbk`. Кодировка внешнего документа: UTF-8.

```json
{
  "format": "DBK",
  "version": 1,
  "author": "ItsFloweS",
  "checksum": "SHA-256 от строки payload",
  "payload": "base64(gzip(UTF-8 JSON проекта))"
}
```

Payload содержит `id`, `name`, `description`, `settings`, `scenarios` и `updated`. У сценария есть `id`, `name`, `enabled`, `nodes`, `edges`. У блока: `id`, `type`, `position`, `data.kind`, `data.params`; опционально `data.label` и `data.breakpoint`. Названия типов и схемы параметров определены в `runtime/catalog.mjs`.

У ребра: `id`, `source`, `target`, `sourceHandle`. Допустимые sourceHandle определяются блоком: `next`, `true`, `false`, `body`, `catch`, `done`. У одного выхода может быть одно ребро. Для повторения используется блок цикла, а не обратное ребро.

Импорт проверяет magic/version, checksum, ограничивает распаковку десятью мегабайтами, проверяет структуру и назначает проекту новый ID. Сценарии сохраняют внутренние ID, чтобы ссылки между ними продолжали работать.

Checksum обнаруживает повреждение, но не является цифровой подписью. Импорт сам по себе не запускает сценарии. Токен, runtime, файлы и рабочие переменные в контейнер не включаются. Пользовательские значения в параметрах схемы сохраняются буквально.
