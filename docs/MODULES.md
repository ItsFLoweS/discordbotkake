# Примеры настройки

## Slash-команда с аргументом

В блоке Slash-команда задайте имя `hello`, добавьте строковую опцию `name`, соедините с «Отправить сообщение». Текст ответа:

```text
Привет, {{options.name}}!
```

Сохраните, запустите бота и обновите команды.

## Кнопка и отдельный сценарий

1. В первом сценарии добавьте к сообщению кнопку с `custom_id` равным `welcome`.
2. Создайте второй сценарий. Удалите автоматически добавленный триггер функции и добавьте триггер «Интерактивный компонент».
3. Выберите `button`, Custom ID `welcome`.
4. Соедините с действием сообщения или выдачи роли.

Пример JSON кнопки:

```json
[
  {
    "type": 1,
    "components": [
      { "type": 2, "style": 1, "label": "Начать", "custom_id": "welcome" }
    ]
  }
]
```

## Условие и ветвление

Блок «Проверка участника»: `permission`, значение `ManageMessages`. Выход «Да» соедините с очисткой сообщений. Выход «Нет» — с ответом об отсутствии прав. Это проверяет автора события; другой ID можно задать явно.

## Цикл

Укажите `count = 3`. Выход `body` соедините с нужными действиями. Последний блок тела оставьте без дальнейшей связи. Выход `done` ведёт к продолжению после всех итераций. В теле доступны `{{temp.index}}` и `{{temp.item}}`. Нумерация с нуля.

## Вызов сценария

В отдельном сценарии оставьте триггер «Функция / сценарий». В исходном добавьте блок «Вызвать сценарий», выберите его из списка, передайте аргументы:

```json
{ "text": "Добро пожаловать!", "userId": "{{user.id}}" }
```

В вызываемой схеме используйте `{{args.text}}` и `{{args.userId}}`. Вызов ожидает завершения, после него выполнение исходной схемы продолжается. Временные переменные общие для этого запуска.

## Ошибки

Из блока Try/Catch ведите `body` к действиям, которые могут завершиться ошибкой, `catch` — к обработчику, а `done` — к продолжению. В catch доступно `{{temp.error.message}}`. Без подключённого catch ошибка передаётся выше.

## Внешний API

HTTP-блок возвращает объект `status`, `ok`, `headers`, `body`. При выходной переменной `response` поле ответа доступно как `{{temp.response.body.name}}`. Коды 4xx/5xx представлены в `status` и `ok`, а не автоматически выбрасываются как исключение. Используйте условие или assert.

## Входящий webhook

Сценарий с событием `ready` открывает слушатель через «Входящий webhook». Порт, например, `8090`; секрет минимум 24 символа берите из `{{global.webhook_secret}}`.

Второй сценарий начинается событием `webhook_receive`. Тело доступно в `{{value}}`, путь в `{{path}}`. Запрос должен быть POST с заголовком `Authorization: Bearer <секрет>`. Сервер привязан к loopback.

## Голос

Укажите ID голосового канала в блоке «Голос и аудио», операция `join`. Затем вызовите `play`, указав аудиофайл относительно папки проекта, например `audio/welcome.mp3`. Последующие play добавляют файлы в очередь. Discord-боту нужны Connect и Speak.

## Файлы и PNG

Папка вложений указана в настройках. «Создать изображение» сохраняет PNG по относительному имени. Следующий блок сообщения может использовать `files = ["{{temp.result.file}}"]`. Для фоновой картинки также нужен локальный относительный путь.

## Экономика и доступ

Начисление, переводы и покупки используют целые неотрицательные суммы, транзакции SQLite и проверку баланса. Кулдаун ежедневной награды — 24 часа. Разрешение административных начислений задайте у slash-триггера или условием перед блоком. Сам факт наличия блока в схеме означает разрешённое автором проекта действие.

## Интерактивные формы

«Показать форму» должен быть первым блоком после slash/context/button-триггера. Нельзя открыть форму после отложенного ответа или паузы. Обработка результата — отдельный сценарий с типом компонента `modal` и таким же Custom ID. Значения полей доступны через `{{fields.ID_поля}}`.
