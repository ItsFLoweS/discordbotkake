# DBK

**Discord Bot Kit · By ItsFloweS**

Desktop-конструктор Discord-ботов: **Tauri 2 / Rust + React / TypeScript + Node.js 24**. Редактор сценариев на React Flow, исполнение через discord.js, встроенная SQLite. Все функции приложения бесплатны. Основной режим — запуск настоящего бота с вашим токеном; симулятор не используется.

## Получить EXE

1. Загрузите содержимое этой папки в GitHub-репозиторий в ветку `main` или `master`.
2. Откройте **Actions → Build DBK Windows**. Workflow запускается после push, для pull request или вручную через **Run workflow**.
3. После успешной сборки скачайте один из артефактов:
   - **DBK-Windows-Installer** — NSIS-установщик `.exe`.
   - **DBK-Windows-Portable** — `DBK.exe` вместе с папкой `resources`. Распакуйте весь архив; EXE требует находящийся рядом runtime.

В комплект включаются Node.js, зависимости Discord, Sharp и FFmpeg. Пользователю не нужно устанавливать Node.js, Rust или npm. Для окна Tauri необходим WebView2; установщик Tauri обрабатывает его установку стандартным способом. Сборка пока не подписана сертификатом издателя.

**В рамках создания проекта локальные установка зависимостей, сборка, тесты и запуск не выполнялись. Проверка `.mjs` через `node --check` не подтверждает работоспособность desktop-сборки. Её результат будет известен после GitHub Actions.**

## Первый настоящий бот

1. Нажмите **Создать проект**. Для первого запуска подойдёт «Чистый лист».
2. В [Discord Developer Portal](https://discord.com/developers/applications) создайте приложение, откройте **Bot** и получите токен.
3. В **Настройках бота** в DBK сохраните токен, укажите Application ID и ID тестового сервера.
4. В Developer Portal включите выбранные privileged intents. Для стартовых настроек это **Server Members Intent** и **Message Content Intent**. Для простого slash-бота ненужные intents можно отключить в DBK.
5. Пригласите приложение на сервер со scopes `bot` и `applications.commands`. Выдайте роли бота права, нужные конкретным действиям. Для выдачи ролей роль бота должна находиться выше управляемых ролей.
6. Нажмите **Запустить**. Дождитесь статуса **В сети**.
7. Нажмите кнопку с круговой стрелкой **Обновить команды** рядом с запуском. Она заменяет команды приложения в указанном сервере, либо глобально, если сервер не задан.
8. Вызовите `/hello` в Discord. Бот ответит через сценарий из двух блоков.

Бот работает, пока приложение открыто. Закрытие DBK останавливает его. После изменений работающего проекта сохраните его и перезапустите бота: текущий запуск использует снимок схемы на момент старта. После изменений slash-опций также обновите команды.

## Как устроен редактор

- У проекта несколько независимых **сценариев**, каждый со своим холстом.
- У сценария один триггер. Добавляйте блоки щелчком или перетаскиванием из библиотеки и соединяйте выход справа со входом слева.
- Условия используют выходы **Да / Нет**. Цикл использует **Повторять / Готово**, Try/Catch — **body / catch / done**.
- Блок **Вызвать сценарий** передаёт аргументы в `{{args}}` и позволяет вынести большую логику отдельно.
- **Shift** выделяет несколько блоков. **Группа** объединяет их визуально. Копирование сохраняет внутренние связи выбранных блоков в текущем сценарии.
- **Ctrl+S** — сохранение, **Ctrl+Z / Ctrl+Shift+Z** — отмена/повтор, **Ctrl+C / Ctrl+V** — копирование/вставка, **Ctrl+D** — дублирование.
- Изменения автоматически сохраняются после паузы. Последние 40 сохранённых версий доступны в настройках.
- Журнал показывает реальные запуски, ошибки, выполненные блоки и временные переменные. Кнопка «Пауза» блока ставит точку останова в настоящем исполнении. Не оставляйте interaction на паузе надолго: у Discord есть срок действия ответа.

Это MVP, а не полная копия всех возможностей DBM. Каталог объединяет близкие действия в блоки с выбором операции. Сложные структуры Discord, например поля embed и варианты select, доступны через JSON в расширенных параметрах. У slash-опций, embed и кнопок есть простые визуальные формы.

## Границы MVP

- Нет публичного маркетплейса и облачного хостинга. Нет платёжных провайдеров, подписок и премиум-ограничений.
- Нет захвата голоса, soundboard, специальных редакторов checkbox/radio в модалках и миграционного UI внешних БД.
- Встроенный магазин выполняет покупку по ID из каталога, а не предоставляет отдельную витрину. Анти-рейд возвращает счётчик и флаг: санкции задаются следующими блоками.
- Счётчики приглашений не определяют автоматически, какое приглашение использовал вошедший участник.
- Google Sheets подключается через HTTP API с вашей авторизацией; отдельного OAuth-мастера нет.
- Cron и сетевые слушатели работают только при запущенном боте. Напоминания и розыгрыши сохраняются в SQLite; просроченные задания возобновляются после следующего запуска. Доставка заданий допускает повтор при сбое между отправкой сообщения и сохранением результата.
- Встроенный webhook слушает только `127.0.0.1`. Для внешнего приёма нужен ваш reverse proxy и `Authorization: Bearer <секрет>`.
- `onboarding_complete` определяется по переходу `GuildMember.pending` из true в false. Это завершение membership screening, а не отдельное универсальное Gateway-событие полного onboarding. Кик определяется через Audit Log; нужны права и intent. Буст определяется изменением участника.
- `.dbk` содержит схему и настройки. Файлы, токен и рабочая SQLite экспортируются/переносятся отдельно.

## Данные и токен

Токен хранится в **Windows Credential Manager** через Rust/keyring. React получает только результат сохранения. При запуске Rust передаёт токен встроенному Node.js через приватный stdin. Токен не сохраняется в документ проекта.

SQLite и папки вложений находятся в системной папке данных приложения (`com.itsflowes.dbk`). Точный путь файлов каждого проекта показан в его настройках. Файловые блоки ограничены папкой проекта и не поддерживают выход через `..` или внешние символьные ссылки.

Значения переменных и произвольные JSON-поля принадлежат пользователю. Не размещайте секреты интеграций непосредственно в блоках, если собираетесь делиться `.dbk`; используйте локальные переменные, например `{{global.database_url}}`.

## Архитектура

```text
src/                     React + TypeScript, редактор и панели
runtime/catalog.mjs      Общий каталог и поля блоков
runtime/engine.mjs       Исполнение графа, переменные, циклы и ошибки
runtime/bot.mjs          Discord Gateway, interaction, команды, расписание
runtime/actions.mjs      Действия Discord
runtime/systems.mjs      Экономика, XP, тикеты и другие системы
runtime/integrations.mjs Сетевые соединения и аудио
runtime/store.mjs        SQLite, формат DBK, версии и валидация
runtime/server.mjs       Приватный JSON-RPC по stdin/stdout
src-tauri/               Rust-host, Credential Manager и файловые диалоги
.github/workflows/       Windows-сборка и артефакты
```

Локальная сборка для этой задачи не требуется. Workflow устанавливает зависимости, проверяет синтаксис runtime, запускает TypeScript/Vite и Tauri, затем публикует установщик и portable-артефакт. Число параллельных исполнений, размер сетевых ответов и шаги графа ограничены для защиты процесса от случайного бесконечного выполнения; это технические ограничения, не платные уровни.

## Документация, учтённая при реализации

- [Discord: interactions и срок ответа](https://docs.discord.com/developers/interactions/receiving-and-responding) — подтверждение interaction в пределах 3 секунд, последующие ответы ограничены сроком жизни токена.
- [Discord: Gateway intents](https://docs.discord.com/developers/events/gateway#gateway-intents) — явный выбор событий и privileged intents.
- [Discord: компоненты](https://docs.discord.com/developers/components/overview) — кнопки, меню и модальные взаимодействия.
- [Tauri: внешние исполняемые файлы](https://v2.tauri.app/develop/sidecar/) — Node.js поставляется с приложением. В DBK процесс запускается Rust-host через `std::process`, без доступа React к произвольным shell-командам.
